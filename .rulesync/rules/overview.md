# エージェント向け作業ルール

このルールはリポジトリ全体に適用する。

`CLAUDE.md`、`AGENTS.md`、`.github/copilot-instructions.md`はrulesyncで生成しています。
直接編集せず、`.rulesync/rules/`を編集してから`npx --no-install rulesync generate`を実行してください。

## Super-Linterの維持

- Super-Linterのワークフロー（`.github/workflows/super-linter.yml`）と、そこで有効になっている各言語の検査を維持する。既存の検査対象と、違反時にCIが失敗する動作を維持すること。
- `GO_MODULES`などの検査を無効化し、別のAction・ジョブ・コマンドへ移すこともSuper-Linterからの離脱として扱う。検査の削除・無効化・移管を独断で行わない。
- 条件分岐、除外フィルタ、`continue-on-error`などで検査を省略したり、失敗を無視したりしない。
- 例外は、ユーザーが対象の削除・無効化・移管を明示的に指示した場合に限る。バージョン更新やCI修正の依頼を、これらの変更の許可と解釈しない。
- 通常の不具合修正や対応版への更新は、検査対象と失敗判定を維持する範囲で進めてよい。互換性不足を解消できない場合は、失敗ログと公式の対応状況を報告し、独断で迂回しない。

`VALIDATE_GO`と`VALIDATE_GO_MODULES`は別の設定です。`VALIDATE_GO: false`だけでGoの検査全体が無効になっていると判断せず、実際の設定とログを確認すること。

## セキュリティ

本サービスは、誰でも認証なしで短縮URLを発行・利用できる公開のURL短縮サービスです。
実装やレビューでは、正しく動くかに加えて、悪意ある入力や操作に耐えられるかを必ず確認してください。

- 短縮対象のURL、使用可能回数、短縮URLのパスなどのリクエストの値は、攻撃者が自由に決められるものとして扱う。
- 値の使い道ごとに、値が文字列やコードの外へ出られないようにする。
  - リダイレクト先やリンクにするURLは、許可するスキームを列挙した許可リストで検証し、`javascript:`や`data:`などスクリプトを実行できるスキームを拒否する。`http`と`https`のほか、`mailto:`など安全なスキームは用途に応じて許可してよい。
  - フロントエンドで入力や保存済みのURLを表示する場合は、HTMLやスクリプトとして解釈されないようにする。
  - 入力をシェルコマンド、ファイルパス、ログの書式文字列として使わない。
- 使用可能回数などの数値は範囲を検証し、URLの長さやリクエストボディの大きさに上限を設ける。
- 使用回数の確認と減算は同じトランザクションで行い、同時アクセスで上限を超えて使われないようにする。
- 認証情報やGCPのサービスアカウントの情報をログ、エラーメッセージ、レスポンスに出さない。
- 失敗した場合は処理を中断し、スタックトレースや内部の情報をレスポンスで返さない。
- GitHub Actionsでは権限を必要最小限にし、書き込み権限やGCPへの認証を持つジョブで、PRからの信頼できないコードやスクリプトを実行しない。
- 新しい外部のActionsはコミットハッシュで固定する。依存パッケージは、公開から日が浅い版を避ける。
- セキュリティ上の問題を修正する際は、その問題が再現しないことを確かめるテストを必ず記述する。
  - 攻撃に使われる入力を使い、修正後は拒否されるなど、結果が変わらないことを確かめる。
  - 修正前のコードではテストが失敗することを確認し、問題を実際に検出できるテストにする。
- レビューで脆弱性を見つけた場合は、公開のIssueやPRに詳細を書かず、まず報告する。
